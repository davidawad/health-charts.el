# AGENTS.md — health-chart.el

Standalone, publishable Emacs package: every biomarker chart kind
(time series with reference/optimal bands, small multiples, sparkline
table, range bars, out-of-range heatmap, multi-person overlay, change
bars) as images drawn by Vega-Lite or gnuplot from templates, or as
unicode text, from plain Lisp data or the biomarker CLI.  Lisp never
draws: the default engine is eas.el (templates/eas/health-KIND.json plus
the adapters and domain transforms of health-chart-eas.el, see
docs/design/eas-migration.md); the gnuplot backend fills
templates/gnuplot/KIND from a chartspec/v1 (docs/chartspec.md).
README.md is the full reference.

## Driving it

Ask the package; don't read source to learn its state.

1. Discover: `(health-chart-describe)` — kinds, shapes, statuses, the
   data source, entry points by verb. From a shell:
   `bin/health-chart describe`.
2. Learn a kind's input: `(health-chart-describe-kind 'bullet)` or
   `bin/health-chart example bullet` (a spec `render` accepts as-is).
3. Check data: `(health-chart-validate KIND DATA)`; a failure names the
   bad element's `:index`.
4. Plan: `(health-chart-explain KIND DATA &rest PROPS)` gives the exact
   renderer and args `health-chart-plot` will use, why that backend, and
   a data summary. Never draws or fetches.
5. Render: `health-chart-render` / `-write` / `-plot` / `-plot-spec`.
   Prefer `:backend 'text` to read a chart yourself; the text renderers
   are deterministic.  `(health-chart-spec KIND DATA)` is the exact data
   a template receives; `health-chart-templates` lists the templates.
6. Fetch: `health-chart-source-query` / `-trend` / `-latest` / `-flag`
   go through `health-chart-source-function`; use
   `health-chart-source-static` to work without the CLI.
   Indicator cohorts: `health-chart-cohort-values` / `-cohort-plot`;
   their pure plans are `health-chart-cohort-values-explain` /
   `-cohort-plot-explain` (every effectful indicator call has an
   `-explain` twin).
7. Reports: Org dynamic blocks (`health-chart`, `health-table`,
   `health-scorecard`, `health-flags`, `health-genetics`,
   `health-genetics-labs`) and
   templates/org; plan a block with `(health-chart-org-explain NAME
   PARAMS)`, a report with `health-chart-org-new-report-explain`.
8. Health: `(health-chart-doctor-checks)` — rows
   `(:name :status pass|fail|skip :detail :remediation)`.

## Changing it

- `make test EAS=/path/to/eas.el` (offline, no display, no biomarker
  install; eas.el is a soft dependency, the eas tests skip without it)
  and `make compile` (warnings are errors) must pass; so must
  `make checkdoc` and `make lint PACKAGE_LINT=<dir>`. Golden fixtures:
  regenerate with `HEALTH_CHART_UPDATE_GOLDEN=1 make test` and review
  the diff.
- New chart kind: a model in -model if it needs one, a text renderer in
  -text, a spec builder in -spec, a gnuplot template
  (templates/gnuplot/KIND.gp) and an eas template
  (templates/eas/health-KIND.json with its example in examples/eas/,
  regenerated by examples/eas-examples.el), then one `health-chart-kinds`
  entry (or `health-chart-register-kind`) and one `health-chart-eas-kinds`
  entry naming the template and the function that builds its slots.
  Range and status logic belongs in a domain transform of
  health-chart-eas.el that calls the package's own rules, never in the
  template or a copy of the rule; `health-chart-eas-parity` must hold.
  The native SVG renderer (-svg) is obsolete: no new features.  The
  doctor and `describe` pick it up; add golden fixtures.
- No drawing code in Lisp for image backends: Lisp decides (rows,
  statuses, bands, ticks, words) in the spec or the eas bindings and
  transforms; templates lay out.  eas templates are one flat namespace
  (`health-` prefix), keep to ASCII or JSON escapes, and cannot cancel an
  inherited encoding (`"x": null`), so put x or y on the layers that use it.
  Values reach tools on stdin, never through a shell.
- The biomarker wire format lives only in health-chart-source.el
  (`health-chart-source-fields`, `-list-keys`, `-cli-args`). Nothing
  else may know JSON member names or CLI flags.  Likewise the indicator
  catalog record format lives only in health-chart-indicator.el
  (`health-chart-indicator-record-paths`).  genetics.el is a soft
  dependency reached only through `health-chart-genetics-functions`
  (never `require` it); gene-to-lab links are data in
  `health-chart-gene-lab-links` (docs/gene-lab-links.md).
- Cohorts and recipe support are data: `health-chart-indicator-cohorts`
  and `health-chart-indicator-evaluators`.  An effectful call gets a pure
  `-explain` twin.
- Errors: `define-error` under `health-chart-error`, data
  `(MESSAGE :code CODE ...)`, message says how to fix it. Never
  message-and-return-nil.
- Status is never color alone: every status shows its glyph and word.
- Synthetic data only, in code, tests and docs.
